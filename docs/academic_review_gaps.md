## §1 背景知识：理解后面内容需要什么

### 1.1 量子线路与编译（最低要求）

**量子线路**：n 个量子比特上的门序列。数学上，一个门是 2^k×2^k 的酉矩阵（k = 该门
作用的比特数）。整条线路的"语义"= 全部门矩阵的乘积（只关心到全局相位 e^{iθ}，
因为物理上不可观测）。

**为什么需要编译（映射）**：
1. **门集限制**：真机只支持少数物理门。天衍-287 支持 {rz(θ), sx, x, cz}——rz 是虚拟
   Z 旋转（无物理误差），sx = X/2 是物理 1Q 门，cz 是物理 2Q 门。
2. **拓扑限制**：cz 只能作用在芯片上物理相邻的比特对（耦合图的一条边）上。
3. **逻辑线路**里的 CX(a,b) 在任意比特对之间——必须转换成 cz + 1Q 门的组合，
   且当 a,b 不相邻时要**插入 SWAP** 把数据"搬运"到一起。

**路由（routing）**：给定初始布局（逻辑比特 → 物理位），按 DAG 顺序执行门；
当前两个比特不相邻时，选择一条边插 SWAP（SWAP 会改变所有后续门的位置），
目标是 SWAP 最少 / 深度最小 / 保真度最高。这是一个 NP-hard 问题（token swapping
的推广），实践中用启发式（SABRE 是代表性工作）。

**final_layout**：全部 SWAP 之后，每个逻辑比特"最终"落在哪个物理位。它和初始的
layout 一起定义了交付线路与原始线路的等价关系：
`U_交付(Π_fin · |ψ⟩) = Π_fin · U_原(|ψ⟩)`（输入态按 layout 嵌入、输出按 final_layout
读出）。**这个记录是一切语义验证的基础**——记错一个比特就会导致语义错误。

### 1.2 KAK / Weyl 分解（理解 A2 块合成需要）

**Cartan 分解（KAK）**：任意 4×4 酉矩阵 SU(4) 都可以写成
```
U = (K1 ⊗ K2) · exp(i(kx·XX + ky·YY + kz·ZZ)) · (K3 ⊗ K4)
```
其中 K1..K4 是单比特 SU(2)（局部门），XX/YY/ZZ 是 Pauli 张量积，"非局部分量"
(kx,ky,kz) 叫 **Cartan 坐标**或 **Weyl 坐标**。这个分解把"两比特门的纠缠能力"
压缩成三个数。

**Weyl 腔（Weyl chamber）**：利用置换/局部等价可以把 (kx,ky,kz) 规约到
π/4 ≥ kx ≥ ky ≥ |kz| 的区域——两个比特门的所有"纠缠类"都在这个多面体里。

**为什么有用**：
- **最小 CX 数**：Weyl 坐标可判定合成该门最少需要几个 CX——ky=0 的"超控门"
  只需 2 个 CX，一般门需 3 个（Vatan-Williams / Shende-Bullock-Markov 的结论）。
- **A2 块合成**：把路由后线路里"同一对物理比特上的连续 2Q 门块"提取成一个 4×4
  酉矩阵 U，KAK 分解后用 3 个 CX（+ 单比特旋转）重新合成——若原块有 12 个 cz，
  合成后只剩 3 个 2Q 门，误差大幅下降。这就是 qiskit O3 的 ConsolidateBlocks +
  TwoQubitBasisDecomposer 做的事。

**当前实现状态**：`qiskit/pure/synthesis.py` 里 `kak_decompose` 是自研的（Weyl 分解
数值解）；但生产 A2 的合成器 `synth_block_analytic` **直接调用 qiskit 的
TwoQubitBasisDecomposer**（这是本次审查 P1-2 的批评点之一，见 §3.5）。

### 1.3 SABRE 路由算法（理解路由层需要）

SABRE（Li, Ding, Xie, ASPLOS 2019）的核心：
1. **Front layer（前沿层）**：DAG 中所有前驱已执行的门。
2. **候选 swap 评分**：每个候选边计算"执行该 swap 后，前沿层门到相邻的距离和"
   （decay 启发式：`Σ_F D + (0.5/n)·Σ_E D`，E 是扩展集/2 跳内的门），考虑
   最近使用次数（decay）避免重复换边。
3. **执行**：选评分最小的 swap；每执行一个门就把它从层里移除、加新门进来。
4. **多 trials**：不同随机种子路由多遍取最优（qiskit O3 默认 20 trials）。

**链（chain）机制**（qiskit SabreDAG 的细节，本项目的移植）：连续作用于同一对
比特的 2Q 门被合并成"链节点"——它们之间的 1Q 门附着在链上，随链一起执行。
这一点是性能关键（dtc 类 1Q 密集线路，我们的复现依赖它才能打平 qiskit）。

### 1.4 保真度模型（理解指标口径需要）

**乘积模型**：`F = Π_gate (1 − ε_gate) × Π_readout (1 − ε_ro)`。
每个门的误差率来自校准数据（逐比特 1Q 误差、逐边 2Q 误差、逐比特读出误差）。

**它的问题**（本次审查 P1-5/P0-3）：
- 不区分门类型：rz 是虚拟门（物理上无误差），却按 sx 的误差率计。
- 无时间维度：芯片有 T1/T2 退相干——线路越深，空闲比特的衰减越大，乘积模型不建模。
- 无串扰：相邻比特同时操作时误差会放大。
- 数值下溢：10^4 门的线路，F 会小到 1e-300 以下变成 0——**比较两个候选时
  乘积值完全失去分辨力**（已改用对数口径 Σlog(1−ε)，本次 P0-3 修复）。

### 1.5 不动点迭代 vs 线性 pass（理解 §3.4 需要）

编译器优化有两种组织方式：
- **不动点循环**：反复运行一组 pass 直到线路不再变化（类似编译器 O3 的
  FixedPoint 循环）。
- **线性 pass 序列**：每个 pass 按固定顺序跑一遍（或固定轮数），不回头。

不动点循环的好处是"充分利用每个 pass"；危险是**振荡与次优不动点**：pass A 改出
的结构被 pass B 改回去，或者局部最小化（门数减少）反而让全局指标（保真度）变差。
本项目的负结果台账（#6/#11/#15/#18/#19）记录了大量此类现象——见 §3.4。

## §3 理论上薄弱的部分（逐项详述）

### 3.1 路由器的调度语义从未被形式化（本次 P0 链归属 bug 的根源）

**问题是什么**：
路由器把"同对 2Q 门链 + 链区间内的 1Q 门"当成一个执行单元（链节点）。
但"哪些 1Q 门属于哪条链"的判定规则，代码里是：
```python
if len(ops[k].qubits) == 1 and deps[k] <= chain_set:
    chain_1q_owner[k] = head
```
**没有正式定义过这个规则应该是什么**。于是出现了一个数学巧合的 bug：

- `deps[k]`（该 1Q 门依赖的前驱 2Q 门集合）为空集时，**空集 ⊆ 任何集合**都成立。
- 一个"所在比特还没有任何 2Q 门执行过"的 1Q 门，会因此被误挂到**任意**正在处理的
  链上——即使它和那条链的比特毫无关系。
- 后果：这个门被延迟到链执行时才发射；而它所在比特上更晚出现的另一个 1Q 门，
  因为空依赖被立即执行——**两个门的相对顺序反转**。同比特 1Q 门通常不对易，
  语义就错了。

**为什么说这是"理论上薄弱"**：不是实现手滑，而是**缺少不变量**。正确的做法是先
写下不变式，例如：

> 不变式（应成立但未写下）：对任意比特 q，若门 g1、g2 都作用于 q 且 g1 在 qasm
> 序中先于 g2，则交付线路中 g1 的执行位置不晚于 g2（当二者之间没有对易重排的
> 授权时）。

以及附着规则：
> 1Q 门 k 可附着于链 C ⟺ deps(k) 非空且 deps(k) ⊆ C 的 2Q 门集合（即它的所有
> 前驱都在链内，等待链是安全的）；空依赖门必须立即可执行。

**审查证据**：最小复现（天衍-287 拓扑，链端非相邻）：
`cz(0,1); rz(2,.5); sx(0); sx(1); cz(0,1); sx(2)` → 修复前交付重叠 0.484；
修复后 1.000000。稀疏线路扫描：60 条随机小线路中 4 条语义错（v4 默认管线），
100 条中 9 条错（v5）——**全部来自这一条规则**。

**当前状态**：已修复（router.py 中 `deps[k] and deps[k] <= chain_set`），
修复后稀疏扫描 0/120 失败。**形式化与回归门禁已完成（2026-11-13）**：
不变式写成 `correctness_theorems.md` T5（顺序保持 + 附着规则 + 内容
末态=final_layout），property 测试
`tests/test_invariants_property.py` 覆盖随机 12 种子逐比特门序 + 最小
复现族；变异验证确认恢复旧规则会让测试变红。

**改进方向**（成本低、价值高）：
1. 在 `correctness_theorems.md` 写清链调度的两条不变式（顺序保持 + 附着规则）。
2. 写 property-based 测试：随机生成小线路，断言"任意两个同比特门的相对顺序
   在存在依赖时保持"。
3. 或者更彻底：把 1Q 门附着规则改为"只附着于**本比特有前驱**的链"（即当前修复），
   并把这个语义写进文档。

### 3.2 fold 家族的坐标帧约定（P0 fold_and_relink bug 的根源）

**问题是什么**：
"折叠（fold）"是后处理的核心技巧：**SWAP 不必真的执行**——交换两个物理位上的
内容，等价于把之后所有门的标签按交换重映射。所以 SWAP 可以被"吸收进标签"，线路里
不留任何 SWAP。

这里有一个本质的坐标系选择：
- **物理坐标**：门标签 = 物理位编号，随物理交换而变（内容在动）。
- **内容坐标**：门标签 = 内容的初始编号，物理交换只是"哪个内容在哪个物理位"的
  记账更新（arr 数组），**内容编号本身不变**。

两种坐标都自洽，但**混用就是 bug**。fold_and_relink 的"保留 swap"分支犯的正是
这个错：它在内容坐标下发射了一个物理 SWAP 门（`swap(arr[a], arr[b])`）**同时**
更新 arr——而内容坐标下物理交换本来就等价于"只更新 arr"，发射 SWAP 就是
**应用了两次**。

**审查证据**：随机 routed 电路 40 条，37 条产物与精确参考（fold_only）不等价
（|ov| 0.2~0.3 量级）；管线扫描中，被选为胜者的 fold_relink 候选 5/5 全错。
修复：该分支改为"放弃折叠"（返回 None，其他候选兜底）。修复后扫描 49/49 安全
放弃、零语义失败。

**为什么说这是"理论上薄弱"**：
1. **坐标系是架构级契约，但只写在注释里**。候选类型 `(circ, final_layout, layout)`
   的三元组没有类型层面的帧标记——把"物理坐标候选"和"内容坐标候选"混进同一个
   列表，靠注释区分。
2. 同理的隐患还存在于：C1 重标记原地改 `inst.qubits`（原地修改 + 共享对象 =
   之前的浅拷贝污染 bug）；measure 的跟随更新新增了两次 bug 才补齐。

**改进方向**（架构重构的核心项）：
- **坐标帧契约已形式化（2026-11-13）**：`correctness_theorems.md` T6
  给出 fold 类候选的命题（U_F = P_arr·U_R；arr=None ⇒ 返回本体且零
  修改；"保留 swap"形态不存在）与结构采用条件；property 测试
  `test_fold_coordinate_frame_property` / `test_fold_abandon_no_side_effects`
  锁定两类形态。类型化（下面的 CandidateResult）仍是执行顺序第 4 项。
- 给候选结果定义类型：`CandidateResult(circuit, frame, output_layout, metrics)`，
  `frame` ∈ {physical, content}，消费方按 frame 决定如何解释标签。
- 或者统一约定：**所有候选输出都用物理坐标**（内容坐标仅作为内部实现细节）——
  这样折叠候选必须在输出前把内容坐标映射回物理坐标（多一次 O(m) 重标记，但
  消除了整类混杂 bug）。
- Inst 冻结（frozen dataclass）或禁止原地改 qubits——每处变换返回新 Inst。
  代价是复制变多（51 万门线路要注意），但消灭了"共享可变状态"这一整类 bug。

### 3.3 保真度模型的物理假设过强（P0-3 + P1-5）

**现状**：`metrics.py` 的乘积模型 `Π(1−ε)`，且：
- rz 与 sx/x 共用同一 err_1q——但 rz 在天衍门集里是虚拟 Z 旋转，物理误差≈0。
- 校准数据里有 T1/T2（`devices/calibration.py`），模型完全不用。
- 无门时间、无空闲退相干、无串扰（ZZ 耦合）、无读出相关性。
- 评分口径不一致：布局预筛选时用**路由线路**算保真度（swap 记 1 个 2Q 误差），
  而交付线路里 swap 会展开成 3 个 cz（记 3 个误差）——**预筛选系统性低估 swap 的
  代价约 3 倍**（审查 P1-5 指出）。

**后果分层**：
- **相对比较**（我们的管线 vs qiskit O3）：只要两边用同一个模型，相对结论
  可信——这是当前所有对比数字的合法性基础。
- **绝对声称**（"真机保真度 0.19"）：不可信——乘积模型不是物理保真度。
- **数值失效**：大型线路乘积下溢为 0，比较完全失效。v7 批次 189/504 条 <1e-12，
  37 条 <1e-100——**非劣化守卫和 L3 仲裁在 37.5% 的样本上是在比较 0 和 0**。
  已修：全部比较口径改为对数保真度 Σlog(1−ε)（本次 P0-3）。

**一个更物理的模型需要什么**（如果要做，工作量不小）：
1. **门时间表**：每类门的执行时长（sx ~30ns、cz ~60ns、读出 ~1μs 量级）。
2. **空闲衰减**：比特在两次操作之间的空闲时间 t → 乘 e^{−t/T1}（能量弛豫）
   与相位项。
3. **rz 误差置 0**（虚拟门）。
4. **swap 折算**：评分时 swap 按 3 个 cz 计。
5. **读出**：与线路末端时间相关的读出错误。
这是文献里"time-aware fidelity"类模型的标准做法；实现上需要调度模拟（按 DAG 层
展开时间轴），本项目的 `metrics.py` 目前没有这个基础设施。

**判断**：在当前竞赛口径下，**对 qiskit 的对比用的是同一模型**，所以相对结论
站得住；把口径换成更物理的模型会让所有数字变化但**相对排序大概率不变**。
建议作为"论文/报告的诚实性声明"处理（明确写"模型为乘积模型，仅用于相对
排序"），而不是立刻重写——除非评委明确要求物理保真度。

### 3.4 不动点优化的势函数缺失（负结果台账的理论根源）

**问题**：后处理曾有"1Q 优化不动点循环"（反复 merge → 分解 → 通勤 → 再 merge，
直到稳定）。这个架构在台账里留下了一系列负结果：
- 误差积守卫（用平台化后的误差积做替换判据）：三线路全面变差（#3）。
- preslide 解碎片：身份路由门数降 15，但达标路由保真度全面变差（#4）。
- H·U·H 共轭吸收：N16 +1.6%、N25 −4.5%（#10）。
- 通勤/循环轮数：产物逐门相同（#6/#7）。
- Tuccil 模板：块级 −66% 被循环吸收，端到端零增益（#1）。

**理论解释（台账里的"统一理论"）**：这个循环**没有势函数**——每个 pass 局部
单调（门数不减不罢休），但"门数"不是"保真度"的单调函数；局部改动会让不动点
漂移到更差的吸引子。数学上：pass 序列是 T = T_k∘…∘T_1，每个 T_i 在门数上非增，
但最终不动点 x* = T^∞(x) 的保真度与初值 x 的关系没有保证（非梯度流）。

**解法（已实施）**：线性架构 decompose_linear——不做循环，把"合并"放在正确的
阶段（u3/rz 层，翻译前后各一次），单遍严格增益移动。这与 qiskit 的 pass 顺序
哲学一致：**每个 pass 只负责自己的局部不变量，整体质量靠 pass 顺序而不是
迭代**。线性版本的实测：qv32 1Q 22,453→15,260、hwb12 墙钟 755s→160s。

**残留的薄弱**：线性架构的"正确 pass 顺序"目前是**经验发现**（对拍 qiskit 的
产物结构逆向出来的），没有文献或理论支撑"为什么这个顺序对"。如果要写论文，
这是一个可以诚实陈述的点：pass 顺序 = 从参照实现的行为反推 + 消融验证，
而非先验推导。

### 3.5 "自研"的边界被打破（P1-2）

**问题**：A2 的块合成器 `synth_block_analytic` 内部 import
`qiskit.synthesis.two_qubit.TwoQubitBasisDecomposer`——**生产管线每次块合成都
在调用 qiskit 的 Weyl/KAK 闭式分解器**。这与项目材料里"qiskit-free / 自研合成"
的表述矛盾，也让"vs qiskit O3"的对比在方法学上混杂：我方 A2 消耗了对手的合成
引擎。

**为什么难修**：qiskit 的闭式解在 Rust 编译产物里，Python 层只是包装；我们
自研的 KAK（`kak_decompose`）只解决"分解"，没解决"从 Weyl 坐标到 3-CX 电路
的闭式角度公式"（这是 Vatan-Williams 论文的公式，实现细节较多）。自研的
torch 拟合路线可行但慢 1-2 个数量级（300-500 步/块）。

**当前处置（诚实化，已提交）**：
- `synth_block_analytic` 拆双后端：qiskit 快路径（默认）+ 自研 torch 回退
  （qiskit 缺失时自动启用，3/3 SU(4) 验证重叠 1.0）。
- 纯 CLI 的"零 qiskit 导入"断言改为"qiskit 只能出现在 A2 后端"，输出如实披露
  当前后端。
- 文档口径全部改为"除可选 2Q 合成器外零第三方依赖"。

**后续可做的事**（按性价比排序）：
1. 从 Vatan-Williams 2004 的公式出发，自研闭式 3-CX 合成器（数学上写得出，
   工程 1-2 天；可彻底去掉 qiskit 依赖）。
2. 或者接受混合架构，在论文里明确声明"2Q 块合成复用 qiskit 分解器，其余全自研"，
   并单独量化该组件的贡献（消融：A2 关闭时性能差多少）。

### 3.7 抽样的验证边界（方法论薄弱点，两次教训）

**两次教训**：
1. 纯相位线路（heisenberg 只有 cx+rz）测不出坐标漂移——"fid=1.0"是空验。
2. 连续均匀随机角度命中不了 rz(π) 模式——Z 剥离的数学错误逃过语义门禁直达
   生产（紧凑子空间验证才抓到 fid=0.0）。

**本次审查又两次应验**：11 条审计样本（都是稠密线路）全部通过，但两个 P0
（链归属、fold 保留 swap）在**稀疏线路**上必然触发——抽样"恰好"没覆盖。

**正确的方法论**（建议写进测试策略文档）：
- 每个机制在设计时**枚举它的触碰模式**：链调度 → 空依赖前缀/链阻塞；
  fold → 有 swap/无 swap、相邻/非相邻、1Q-only 比特；合成 → 特殊角
  (0/π/2/π)、随机角。
- 验证输入要**覆盖模式而不是随机抽样**：固定角用例 + 离散角随机 + 结构化
  随机（稀疏/稠密、1Q-only 前缀）。
- 管线级验证要覆盖**所有候选胜出路径**（fold_only/fold_keep/fold_relink/
  裸路由），因为候选选择是数据依赖的。

## §4 与文献/参照实现的差距（逐组件）

### 4.1 路由：SABRE 复现 vs 原始论文 vs LightSABRE

| 维度 | 原始 SABRE (Li et al. 2019) | qiskit 2.5 (Rust SabreSwap) | 本项目 |
|---|---|---|---|
| 基础评分 | Σ_F D + w·Σ_E D | decay 启发式（0.5/n 权重） | 对齐 qiskit（w_ext=0.5/n，本次修复后） |
| 扩展集 E | 有（2 跳内门） | 有 | 有（此前默认关闭——配置漂移 bug 已修） |
| decay | 论文版按边计数 | decay(0.001, 5) | 参数保留、默认关（单用混合效果，见台账） |
| 前瞻 | 无 | 无（rust 无前向模拟） | **有（双步前瞻，自研）** |
| trials | 单次 | 20 | 16（线程并行） |
| 链合并 | 无 | SabreDAG 链节点 | 有（语义修复后） |
| 噪声感知 | 无 | 无（noise-adaptive 是另一篇） | 无（路由评分层面关闭；布局层有 RL 噪声感知） |

**差距结论**：
- 我们是"qiskit SabreSwap 的语义复现 + 前瞻增强"，不是 LightSABRE 论文算法。
  **叙事上不能写"实现了 LightSABRE"**——写"对齐 qiskit O3 的 SabreSwap 语义，
  并加入自研双步前瞻"是准确的。
- 路由层面与纯路由对照（dtc_100 类）：我们 1,470 vs qiskit 1,395（差 5%），
  dtc 类 qiskit 的 decay 机制仍未完全复现（decay 在 rust 里，语义只能从行为
  反推）。这是"复现深度"的边界，论文里要写清楚。

### 4.2 布局重标记：VF2PostLayout

| 维度 | qiskit VF2PostLayout | 本项目 relabel_vf2 |
|---|---|---|
| 子图同构 | networkx VF2（Cordella 2001） | networkx VF2（相同算法库） |
| 激活规模 | 全部活跃节点 | ≤20 活跃节点（超限走部分嵌入） |
| 评分 | 完整指标（1Q/2Q/读出/退相干加权成本） | 仅 2Q 边误差加权 |
| 试验机制 | 多候选 + 分数仲裁 | 精确嵌入内选优 + 部分嵌入（自研扩展） |
| 禁用比特 | 处理 | 处理（审查后修复） |

**差距**：规模上限（20）与评分维度（仅 2Q）。实际影响：大型线路（>20 活跃节点）
退化为"部分嵌入"（局部搜索最大化可嵌入边权重），效果弱于精确嵌入。

**决策（2026-11-12，详见 docs/vf2_postlayout_explained.md §8）**：
- **分块 VF2 否决**——真实数据（587 大线路）交互图几乎全部连通，分块收益≈0；
  块间跨边使独立嵌入不成立；且被预算机制取代。
- **自研 VF2++ 优先（方案 B）**：VF2 五规则剪枝 + VF2++ 节点排序 + 搜索内
  增量打分（log 空间，含 1Q/读出项）+ 分支限界 + 硬预算（检查在递归内部，
  根治 graphstate_50 类事故）。学习 qiskit 架构，不强求创新。
- **rustworkx（方案 A）仅作备用**：其 `vf2_mapping` 无搜索内打分/剪枝接口
  （实测 0.18.1），单独用不能复刻 qiskit 的集成度。
- 预注册判据：≤20 与 networkx 最优分数一致；>20 活跃精确嵌入成功率 ≥50%；
  单次 ≤8s、全管线墙钟增幅 ≤10%；large 抽样 fid/depth 不劣化；零非法。

### 4.3 1Q 合成：qiskit euler 分解器 vs 我们的 B8 合成器

- qiskit 的 `Optimize1qGatesDecomposition` 用多候选（ZSX/ZSXXZ 等）+ 误差
  评分选优；我们的 `_u3_to_rzsx_min` 实现同构候选集（ZSXXZ + 零角省略 +
  θ=0/π/2/π 特例），按门数最少选。
- **审查实测**：对同一 4-5 门游程，qiskit 的分解器给出与我们相同的门数——
  合成层已对齐（补充十八的结论仍成立）。
- 剩余差距在**块结构**（每块 1Q 密度），而非 1Q 合成器本身。

### 4.4 通勤消解：CommutativeCancellation

- qiskit 的实现（Rust）：H/X/Z 自逆门全局通勤 + 对消，跨 cz 收集。
- 我们的实现：窗口版（`commute_cancel_cx`）+ 线性分解里的对角累加器
  （rz 跨 cz 精确对易，全深度单遍）+ rz(π) 的语义由 merge_run 矩阵乘自动处理。
- **等价性**：线性分解后 qv32 的 1Q/深度/logf 三项全部优于 qiskit O3 对照——
  机制层面已经"打平或更好"，但**不是**同一个算法（我们的累加器语义是自研的，
  且经过了 Z 剥离的负结果教训）。

### 4.5 块合成：ConsolidateBlocks + TwoQubitBasisDecomposer

- qiskit：收集同对连续 2Q 块 → 4×4 酉矩阵 → Weyl 分解 → 最小 CX 数的闭式电路。
- 我们：同样的收集语义（"uninterrupted" 块，外比特 1Q 是硬边界——审查 P0 修复
  的语义）→ `synth_block_analytic`（**调用 qiskit 的分解器**，见 §3.5）。
- 差距：后端依赖（qiskit）与模板结构（我们的 21 参数 3-CX 模板 vs qiskit 的
  分情况闭式解，后者对特殊门能落到 2 CX）。

### 4.6 优化循环：qiskit O3 的 FixedPoint vs 我们的线性架构

- qiskit O3 管线：`ConsolidateBlocks → Optimize1qGatesDecomposition →
  CommutativeCancellation → ...` 的 FixedPoint 循环，最后 `VF2PostLayout`。
- 我们曾模仿不动点（`decompose_to_platform_v2`），遭遇一系列次优不动点问题
  （台账 #3/#4/#6/#10/#15/#18/#19），最终改为线性 pass 序列（`decompose_linear`）。
- **理论差距**：qiskit 的不动点循环在**他们的 pass 语义**下收敛良好（pass 都
  是单调的清理型 pass，不引入新的优化空间）；我们的旧循环把"移走-合成"混在
  一起产生了振荡。线性架构是对"pass 语义设计"的一次重新理解——这是本轮
  最重要的方法论产出。

### 4.7 噪声感知布局（RL CO-MAP）——与前人工作的关系

- qiskit 的 O3 布局对噪声不敏感（VF2PostLayout 有噪声评分但只是后置修正）；
  文献中的 noise-adaptive 布局（Murali et al. 2019 ASPLOS）用误差率加权距离。
- 本项目的 RL 布局（CO-MAP：图 Transformer 策略 + 多起点解码 + 局部搜索 +
  噪声感知距离）是**原创贡献**，与 qiskit 差异最大的一块。
- 审查建议：论文里要单独量化"RL 布局的贡献"（消融：固定布局 vs RL 布局），
  避免与后处理改进混在一起。

### 4.8 基准与方法学

- 对比基线：RL 布局 + qiskit O3（用同一 target/校准数据——这一点是公平的，
  审查也确认了误差率输入同源）。
- 指标：乘积保真度（双方同模型）——**相对结论有效，绝对值不可当真机保真度**。
- 与文献的差距：没有用论文标准的 benchmark（如 RevLib/QASMBench 全集）和
  标准指标（如 fidelity vs depth Pareto），是自建 587 条分层集——评审可能会问
  代表性。

## §7 一页总结

**最强的部分**：恒等式层（1Q 分解/翻译/KAK 比特序/链矩阵/fold 置换）数学精确，
审查代理独立复验全过；线性分解架构解决了不动点振荡，指标三项优于 qiskit O3。

**最弱的三处**：
1. **调度语义无形式化**（链归属 bug 的根源）——不是数学难，而是没写下来。
   **已补（2026-11-13）**：T5 + property 测试，P0 形态已有回归门禁。
2. **坐标帧约定靠注释**（fold bug 的根源）——架构级契约没有类型系统或文档保证。
   **文档层已补（2026-11-13）**：T6；类型化（CandidateResult/Inst 冻结）
   仍在执行顺序第 4 项。
3. **保真度模型是代理指标**（下溢/无物理时间/rz 计误差）——相对比较有效，
   绝对声称要谨慎。

**叙事上的三个必须如实**：
1. 路由器是 qiskit SabreSwap 的语义复现 + 自研前瞻，不是 LightSABRE。
2. A2 的 2Q 块合成器默认调用 qiskit（已披露，可自研替换）。
3. "587 全样本 fid=1" 不成立——只有抽样验证（已更正）。

**下一步的先后**：不变式文档与测试（便宜且立刻防复发）→ 自研合成器（去依赖）
→ 类型化重构（根治状态类 bug）→ 物理保真度（论文级）。
